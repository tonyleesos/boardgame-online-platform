# 璀璨寶石實作說明

## 進入遊戲

沿用平台會員登入、暱稱、房號、準備、房主與 presence。支援 2–4 個座位，包含真人與 AI。大廳「單人練習 · 與 AI 對局」可選擇 1–3 位 AI 與輕鬆／標準難度；朋友房可由房主新增／移除 AI。房主在等待區選擇玩法，設定改變後真人重新準備，AI 保持準備。相同瀏覽器分頁共用身份，請以不同瀏覽器或獨立無痕視窗測試不同玩家。

手機直向（寬度 600px 以下）使用動態視窗高度配置，玩家、貴族、III／II／I 階市場、寶石庫及自己的保留卡同時呈現，不需捲動主棋盤。東方擴充的六張額外卡與獨立牌堆也留在同一畫面。卡牌左上為聲望，右上為永久折扣，下方為成本；點卡牌開啟完整資訊與購買／保留操作。寶石庫移除說明文字，直接選取後再確認。自己的寶石明細與永久折扣可點玩家收藏查看；桌機保留底部明細欄。

交易紀錄、貿易站、完整收藏及規則由頂部按鈕或玩家面板開啟原生對話框，較長內容在對話框內閱讀。手機隱藏重複的平台標頭、玩家清單和底部收藏欄，保留房號複製及離開房間。支援鍵盤焦點、斷線停用操作與 reduced motion。

## 原創資料與規則界線

2026-09-15 介面更新：手機貴族／城市縮成一列並直接顯示需求，亦可點開詳細條件。玩家面板以五色小卡呈現購卡張數，另顯示寶石總數、保留張數與聲望；完整卡名、各色寶石和永久加成在收藏視窗呈現。輪到的玩家有紅點，橫幅同步顯示目前行動者與待完成階段；手機要塞階段可直接從橫幅略過。寶石動畫以玩家的總數位置為目的地。

寶石庫沒有模式分頁：單一顏色依序點選為 1 → 2 → 0 枚（庫存未滿 4 時只能 1 → 0）；異色可各選一枚、最多三色。已選同色兩枚時不能加別色，混選時再次點已選顏色會移除，也可按清除重選。仍需按「拿取」才送出，伺服器再次驗證庫存與數量。商隊原本的四色能力已調整為 +1 聲望，所有玩法都遵守三色上限。

操作動畫改由伺服器發布 `activities`，保留最近 40 筆已成功動作。所有玩家依 revision 排隊播放拿取、付款、購卡、保留、退回、貴族及要塞變動，略過也有文字提示。暗牌只含階級與來源，直到公開購買後才可顯示卡面；重新載入不重播載入前的操作。動畫不擋操作，減少動態效果設定會保留文字回饋。

本實作是規格要求的 Splendor-inspired 遊戲。所有 SVG 場景、寶石造型及名稱為專案原創，沒有複製官方插畫、標誌、規則書文字或完整資料集。原創示範卡組為 I 階 40、II 階 30、III 階 25 張，10 位貴族、5 座城市及 30 張東方卡。每階分別洗牌，成本與效果完全由資料定義。

基礎規則：2／3／4 人時每色有 4／5／7 枚，黃金固定 5 枚。拿取 1–3 種不同寶石，或庫存原先至少 4 枚時拿 2 枚同色。黃金僅由主要保留動作取得。保留上限 3 張；暗牌身份只有本人可見。卡牌折扣永久有效，支付不足以黃金補足。回合結束超過 10 枚必須精確退回。每回合最多一位貴族；多位符合時自行選擇。達 15 聲望後完成本輪，依聲望、較少已購卡、共享勝利判定。

四種擴充各自獨立，採以下**原創示範效果**，不宣稱重現商業擴充的完整牌表或所有效果：

| 模組 | 本平台規則 | 測試方式 |
| --- | --- | --- |
| 城市 | 3 座城市取代貴族，要求聲望、指定加成及不同加成種類。符合任一城市即觸發最後一輪；達標者中最高聲望勝出，同分共享。 | 選「城市」確認沒有貴族。累積卡牌達到任一條件，確認不會單因 15 分結束。 |
| 貿易站 | 回合結束解鎖永久能力，不重複領取。商隊：加 1 聲望（所有玩法拿取最多三色）；金匠：1 黃金抵 2 個跨色缺額，向上取整；倉庫：上限 12；珠寶行：每 2 鑽石加成加 1 分；商會：加 3 分。 | 展開貿易站查看需求；達成後檢查聲望、付款與上限。 |
| 東方之路 | 各階另有 2 張可見卡與獨立牌堆。雙倍：本色加成 +2；複製：本色 +1 再複製一個既有顏色 +1；歸還：購買後移除一張 I 階已購卡，失去其分數／加成；保留：可額外保留一張目前公開卡，不給黃金；邀約：可鎖定一位未受邀貴族，僅邀約者符合條件後可取得。 | 購買東方卡，在同一操作視窗選加成、歸還卡、免費保留或邀約對象。必要選擇不可略過，其餘可略過。 |
| 要塞 | 每人 3 座。主要購買後可放置 1 座到未受敵方保護的市場卡、移除 1 座對手要塞或略過。敵方不可購買／保留受保護的卡。3 座集中在一張卡上時，主要行動後可額外付費購買該卡一次或略過；額外購買不再次放置要塞。卡離開市場時歸還所有要塞。 | 購買後點市場卡放置／移除；集齊 3 座後確認額外購買階段與支付。 |

貿易站在本回合結束才啟用，所增加的代幣上限／拿取量於下回合生效。東方歸還卡的成本折扣先按購買前收藏計算，成功支付後才移除卡；複製效果固定複製選定顏色，不會因原參考卡日後離開而消失。邀約貴族不立刻給分。城市條件達成後資格保留至終局。

競技模式不顯示可買卡高亮與付款建議；仍保留卡牌價格、公開持有資訊及伺服器合法性驗證。

## 架構與保密

- `functions/src/shared/splendor.ts`：共用型別、原創牌表、正規化與純函式。購入卡是折扣／聲望的真實來源，快取不接受客戶端提供。
- `functions/src/splendor/engine.ts`：設置、主要操作、強制階段、擴充效果及回合結算。先複製狀態再驗證與修改，錯誤操作無部分副作用。
- `functions/src/splendor/bot.ts`：AI 決策函式只接受公開狀態及本人保留卡，不取得 Session、牌堆順序或其他玩家私人資訊。沿用平台 `advanceBots`，一次交易最多推進一個 AI 動作，有版本檢查與節流；每個動作仍經同一套遊戲引擎驗證。標準難度評估成本缺口、永久加成、聲望及貴族／城市條件；輕鬆難度對可購買卡採更多隨機選擇。兩種難度皆處理強制退幣、貴族、五種東方效果與要塞。
- `functions/src/index.ts`：沿用 `createRoom`／`roomAction`／`gameAction`。Authenticated uid 決定操作身份，房間 transaction 原子寫入，`gameId:revision` 擋下過期與重複送出。
- `sessions/{code}/public/splendor`：公開市場、庫存、玩家、收藏、貴族／城市、紀錄。暗牌只有 slot、階級、來源與可見性，沒有 cardId。
- `sessions/{code}/splendorPrivate/{uid}`：本人保留卡 slot → cardId 對應；只有本人能讀。
- `sessions/{code}/secret/splendor/decks`：牌堆顺序，客戶端完全不能讀。
- 所有遊戲資料都禁止 client write。只有 presence 沿用既有受限寫入。
- `client/src/games/splendor/`：SVG 視覺、響應式棋盤與對話框。沿用共同 Firebase 初始化、`useRoom`、`useAction` 與 `GameDialog`。

重新載入會訂閱公開狀態及本人暗牌，回復退幣、選貴族與要塞待決階段。暫時離線保留座位，不自動替玩家作策略選擇，也不能清理仍在遊戲中的離線座位。明確離開會中止本局；其他玩家可以由房主重新開局。再開一局清除舊遊戲與私人資料。

## 驗證

```sh
npm run lint
npm test
npm run build
```

啟動 `npm run emulators` 後：

```sh
node tests/splendor-integration.mjs
npx playwright test tests/browser/splendor.spec.ts
npx playwright test tests/browser/splendor-practice.spec.ts
npx playwright test tests/browser/splendor-layout.spec.ts
```

`npm run test:integration` 會啟動 Emulator 並執行所有遊戲的服務測試，包含璀璨寶石。Java 設定見主 README。

單元測試使用 seeded shuffle。測試涵蓋主要操作、付款、強制退幣、貴族、終局、各型東方效果、要塞保護、貿易站與城市；五種玩法都從正常開局開始跑完整局並檢查寶石守恆。整合測試經電子郵件／密碼 Auth、callable Functions 與 RTDB security rules，驗證五種玩法完整對局、2–4 人、未授權讀寫、暗牌、同時提交與重連，不修改資料庫狀態來推進遊戲。瀏覽器測試以不同 context 驗證 2／3／4 玩家、360／390／768／1280 寬度、購買預覽、拿取、保留、重連與雙人完整對局。畫面輸出位於 `.tools/screenshots/splendor-*.png`。

AI 測試另以 5 種玩法 × 2 種難度 × 3 種人數 × 3 個種子跑 90 局，檢查自動完成、動作合法性、寶石守恆及不讀取其他人的暗牌。練習瀏覽器測試驗證 1–3 位 AI 自動準備／行動、單人完整對局、重連、競技模式與城市／貿易站畫面。

`splendor-layout.spec.ts` 在本機 Emulator 注入專用版面情境，驗證五種玩法、四人皆有多張購卡且自己保留三張的 320×568／390×740 畫面：主頁無捲動、主要操作未裁切、卡價不蓋住聲望，以及收藏、保留卡與交易紀錄視窗。測試結束刪除專用房間；這些版面情境不作為規則合法性的證明。實際多人與 AI 對局仍由前述操作測試驗證。

## 正式上線

2026-09-11 已將 Functions、Realtime Database rules 與 Hosting 同步部署至正式專案，修復「此遊戲尚未開放 [400]」。正式 API 及手機尺寸瀏覽器皆已成功建立 1 位真人＋2 位 AI 練習桌、保留暗牌，並完成兩位 AI 的回合；另確認暗牌與未登入存取限制。驗證用房間與帳號已清除。

正式專案以 `.firebaserc` 的 `default` 為準（目前為 `boardgame-online-platfor-c5ebd`），並與 `client/.env.local` 保持一致。沿用既有 Firebase 設定，不需新增索引、Firebase App 或 callable 名稱。Functions、Realtime Database rules 與 Hosting 必須一起更新；只部署前端會出現「此遊戲尚未開放 [400]」。部署者使用有專案權限的登入帳號執行：

```sh
npm run deploy
```

若只部署前端，舊 Functions 不認識 `splendor`；若規則未更新，本人暗牌訂閱會被拒絕。
