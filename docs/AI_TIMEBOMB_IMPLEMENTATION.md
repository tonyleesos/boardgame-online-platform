# AI 玩家與驚爆倫敦：危機進化

本次將驚爆倫敦從舊 Socket.IO 原型遷移至 Firebase，並讓它與 Avalon 都支援單人練習。原型和中文規則書留在 `server/`，新遊戲使用 `functions/src/timebomb-engine.ts`。

## 遊玩入口

1. 輸入暱稱，在遊戲目錄選「單人練習 · 與 AI 對局」。
2. 先在大廳選「驚爆倫敦」或「驚爆倫敦：危機進化」，再選人數與 AI 難度。版本固定於房間，不能混用。
3. 建房後準備、開始。AI 自動準備並在遊戲中行動。
4. 查看自己的身份與本輪手牌組成，送出解除引線數量宣言。
5. 持有剪刀時點其他人的蓋牌；遇到能力選擇時依提示操作。房主在剪線結果點「繼續剪線」或下一輪。
6. 終局公開陣營，可保留同桌 AI 再玩一局。

好友房的房主可在開局前新增／移除 AI；練習桌不接受其他真人加入。人數包含 AI：Avalon 5–10 人、驚爆倫敦原版 4–8 人、危機進化 4–6 人。

## AI 如何決策

使用規則與評分策略，不呼叫外部聊天模型、不需要額外金鑰。標準難度利用公開紀錄推測；輕鬆難度增加隨機選擇。這是可完成合法對局的練習對手，推理及發言尚無真人的豐富程度。

- Avalon：根據任務結果評估成員；邪惡方也使用其角色依法知道的同伴情報。可組隊、表決、任務出牌及刺殺。刺殺僅使用公開表決的簡單推測，不偷看梅林。
- 驚爆倫敦：好人依自己的手牌數量宣言；壞人會虛張聲勢。依宣言扣除本輪已揭露的解除引線，估計目標剩餘比例。每張蓋牌位置一律隨機選，不知道隱藏牌面。拆除／移除保護依陣營與公開危險程度選擇。
- 「圓桌發言」是行動對應的繁中短句；不是自由對話，也不會分析真人外部聊天。

策略函式只接收該遊戲的公開狀態與 AI 自己的私人資訊。伺服器的派送層持有 session，但不將其他人的私人資料或 `secret` 傳給策略函式。

`advanceBots` 每次以 RTDB 交易處理一個合法行動，檢查真人成員資格、遊戲 revision 與至少 650 ms 的節奏限制。多個瀏覽器同時觸發不會重複行動。前端約每 1.1 秒觸發一次，確定沒有 AI 待辦時停止，等狀態變更再繼續；暫時節流則重試。所有真人關閉頁面後暫停，不提供背景排程對局。

## 原版驚爆倫敦

依 [IELLO 官方原版規則](https://iellogames.com/wp-content/uploads/2016/10/Time_bomb_rulebook_EN.pdf)。4–8 人，牌庫有 N 張解除引線、1 張炸彈、4N−1 張安全引線。安全引線無效果，炸彈立即引爆，集滿 N 張解除引線即勝。最多四輪，每人依序 5、4、3、2 張，每輪剪 N 次。

4／5 人角色池是 3 好人、2 壞人；6 人為 4 好人、2 壞人；7／8 人為 5 好人、3 壞人。4 人與 7 人局各有一張角色不發且不公開。

查看本人手牌時逐張顯示卡面：安全引線用完整銅色線路、解除引線用綠線與剪刀、炸彈用鐘錶裝置。只保留短牌名與一行位置提醒；同類牌排在一起，不能推算桌上實際牌序。危機進化也使用相同的逐張圖案顯示方式。

## 危機進化規則

依 [IELLO 遊戲頁](https://iellogames.com/games/timebomb-evolution/)、[官方英文基礎規則](https://iellogames.com/wp-content/uploads/2020/01/TIME-BOMB-EVOLUTION_rulebook_EN_Light.pdf)、[官方進化補充規則（法文）](https://iello.fr/wp-content/uploads/2020/01/TIME_BOMB_EVOLUTION_FeuilletEvolution.pdf)，並對照專案 `server/TIME BOMB EVOLUTION_rulebook_CN.pdf`。

- 4／5 人從 3 夏洛克、2 莫里亞蒂角色中分配；4 人隨機棄掉 1 張且不公開。6 人為 4 夏洛克、2 莫里亞蒂。
- 從六色選與人數相同的顏色，每色 5 張；隨機移除與人數相同的炸彈，再加入等量解除引線。每人初始 5 張。
- 自己只知道剩餘牌的組成，不知道蓋牌位置。每輪剪線數通常等於玩家人數；剩餘牌全部重洗，下一輪每人 4、3、2 張。
- 被剪的玩家接過剪刀。找到與人數相等的解除引線，夏洛克立即勝；炸彈引爆或第四輪結束，莫里亞蒂勝。
- 舊平台的 `standard` 是危機進化的基礎變體，並非原版驚爆倫敦。僅為既有房間保留；新建房由 `timebomb-classic` 固定使用原版，`timebomb` 固定使用進化能力，伺服器拒絕混用版本。
- 進化規則的解除引線必須選擇一種已揭露、未受保護且非黃色的炸彈加上保護；無合法選擇時只增加成功數。保護阻止張數引爆，特殊能力仍會觸發。

| 顏色 | 進化效果 |
| --- | --- |
| 綠色 | 未受保護時第 3 張引爆。 |
| 粉紅 | 連續兩張粉紅立即引爆，跨輪也算，拆除保護無法阻止；普通張數引爆仍是 4 張。 |
| 黃色 | 無法加上拆除保護。 |
| 藍色 | 每張都移除一種顏色的保護；移除後已達爆炸張數則立即引爆。 |
| 橘色 | 進入第四輪時，依已揭露橘色張數減少該輪剪線額度，即使橘色已受保護。第四輪中新揭露的橘色不再扣額度。 |
| 紅色 | 下一張必須剪隨機指定玩家，可能指定剪刀持有者自己。跨輪仍有效；同輪指定者已無牌時直接交剪刀給他，沒有額外剪線。 |

數位版讓每人每輪提交一次數字宣言，方便 AI 參與，宣言可以說謊且不以真實牌面驗證。開局剪刀持有者隨機選擇，取代實體版的「最近去過倫敦的人」。剪線結果由房主確認繼續，讓玩家有時間閱讀。

## 資料與測試

`public.timebomb` 僅包含可公開狀態、剩餘牌槽、宣言與剪線紀錄；`timebombPrivate/{uid}` 只包含本人陣營、本輪數與剩餘手牌組成；真正牌序在禁止客戶端讀寫的 `secret.bombHands`。終局才公開角色。

- 62 項單元測試：包含原版 4–8 人牌庫／角色、即時引爆、六色能力、跨輪與稀疏 RTDB 陣列、非法操作、基本勝負，以及 60 局驚爆倫敦和 10 局 Avalon AI 模擬。
- `npm run test:services`：兩遊戲完整 Emulator 對局、私密資料規則、容量、重開、並發、練習桌隔離及 AI 操作資格。
- `npm run test:e2e`：多人 Avalon；8 人原版、6 人進化及 5 人 Avalon 單人 AI 對局；圖案手牌、重連、重開與五種畫面寬度。

## 美術與正式環境

卡面採原創蒸汽龐克人物、齒輪、剪線與倫敦插畫，加上六色框線、名稱與符號。參考提供照片的題材與氣氛，未使用照片裁切作卡面。素材、格位及生成提示詞見 [卡牌素材說明](../client/public/art/README.md)。

正式 Firebase 尚未部署：目前帳號無法存取使用者指定的 `boardgame-online-platform`，實際 database URL 尚待取得。需按 [README](../README.md) 完成 Auth、Database、Functions 環境設定，部署本次新增的 `advanceBots`、其他 Functions 與更新後的 rules，再部署前端。單獨更新 Hosting 不會啟用 AI 與新遊戲。
