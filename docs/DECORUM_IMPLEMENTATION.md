# 同房異夢實作對照

本專案依 `DECORUM_GAME_IMPLEMENTATION_SPEC.md` 延伸原平台，遊戲名為「同房異夢」。所有示範條件、劇本與家具 SVG 均為本專案原創，未收錄商業版劇本或插畫。

| 里程碑 | 現有實作與驗證 |
| --- | --- |
| D1 遊戲入口 | 既有遊戲目錄、2–4 人房間、原創劇本選擇、平面圖 |
| D2 房屋引擎 | 加入／移除／同類替換／粉刷／滿意略過；四人臥室交換與容量驗證 |
| D3 條件引擎 | 純函式與組合式條件；四個劇本均有測試專用合法解法 |
| D4 多人同步 | callable 操作、RTDB transaction、階段 token、即時房屋與回應 |
| D5 秘密條件 | 伺服器分配與判定，RTDB 禁止讀他人條件、根節點與秘密資料；指定收件人分享 |
| D6 雙人流程 | 入住、輪流佈置、回應、15／20／25 輪談心、30 輪上限、成功／失敗與揭曉 |
| D7 三／四人流程 | 五次會議、單向分享與撤回前次存取、全員回應後換人、四人室友交換 |
| D8 介面 | 房間／家具圖示、心願圖卡、表情回應、圖卡式會議、房間前後對照、愛心時程、終局房屋縮圖、行動裝置抽屜與 reduced motion |

## 資料與責任

- `functions/src/decorum/engine.ts`：合法行動、階段、回合、會議與終局，僅可信伺服器可操作。
- `functions/src/shared/decorum-conditions.ts`：獨立 React／Firebase 的條件評估。
- `functions/src/decorum/scenarios.ts`：僅伺服器持有條件與分配；shared 檔僅提供目錄與劇本摘要。
- `client/src/games/decorum/ConditionVisual.tsx`：只呈現已獲授權讀取的條件，以圖示與短標籤表示範圍、物品、顏色、風格、數量及邏輯；完整文字直接顯示，並保留無障礙名稱。
- `RoomActionSheet.tsx`／`RoomScene.tsx`：確認前的局部房屋預覽與終局縮圖。預覽不修改共享房屋，確認後仍由伺服器完整驗證。

## 驗證

`npm test` 涵蓋引擎行動、條件 primitives、AND／OR／NOT、滿意狀態反轉、立即勝利、失敗、所有會議時程、分享歸屬與解法。

`npm run test:services` 在 demo Emulator 驗證身份／讀寫權限、並發操作、非法條件／收件人拒絕、私人分享與離席／重開。

`npm run test:e2e` 使用獨立瀏覽器身份，對四個劇本驗證入住、合法回合到首次會議、圖卡分享、房屋操作、表情回應、重連、多人成功及重開；手機寬度含 360／390，另驗 768／1280。

## 數位版選擇

依 [Floodgate Games 官方規則第 3、4、6 頁](https://media.floodgate.games/rule-books/Decorum-Rule-Book.pdf)，實體版是燈具、擺飾、壁飾三類，只有 12 種有效的類型／顏色／風格組合，各 4 枚，共 48 枚。不同插畫不代表不同規則屬性；並非 3 × 4 × 4 種可自由搭配的物品。本平台沿用 12 種有限目錄，但配色與風格對應屬原創，並未逐項重製實體版。四間房間每種物件各一格，自然限制同款最多使用四件。

2026-09-14 更新：第一次合租每人 4 項，其餘劇本每人 5 項；難度分別為 2／3／4／4。加入 `emptySlotCount`（只數物品空格）、`distinctCount`（計算不同顏色或風格種數，重複物品不重複計種）、跨房間數量與配色限制。四人原本要求同住者使用不同牆色，必須透過換房才能化解；現在改成可同房共存的黃色／藍色物品需求，保留換房及全屋限制。

四個劇本以 ID 對應整組願望，避免摘要重新排序造成錯配。測試對所有 34 種條件分配（2! + 2! + 3! + 4!）從入住走完合法操作與回應，驗證全員同時勝利；另驗證四人換房後仍可同時滿足。解法只存於測試。既有對局保留已發出的條件，新條件在新局開始時套用。

家具目錄的同一設計可重複使用。多人每位非行動者各回應一次後換人；離線可等重連，離席或清理則中止，避免遺留無法完成的局。多人會議的新分享取代舊分享；介面撤回不能抹除玩家已記住的資訊。評分為已完成條件 × 3，合作成功另加剩餘愛心 × 2。

提前談心及桌面拖放為規格中的選配，尚未加入。所有基本操作皆可點選完成。本機驗證不等同正式部署，正式上線仍需部署前端及 Functions，並使用儲存庫中的 RTDB 規則。
